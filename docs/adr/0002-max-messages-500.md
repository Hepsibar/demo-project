# ADR 0002 — 메시지를 마지막 500개로 tail-trim

- Status: Accepted
- 관련 코드: `main.py` (`MAX_MESSAGES = 500`, `all_messages[-MAX_MESSAGES:]`)

## Context

카카오톡 로그는 수천~수만 줄에 이를 수 있다. 전량을 모델에 보내면 토큰 한도 초과·비용 급증·지연이 발생한다.
어떤 형태로든 입력을 잘라야 하는데, **무엇을 남길지**가 품질을 좌우한다.

## Decision

유효 메시지가 `MAX_MESSAGES`(=500)를 초과하면 **가장 최근 500개**만 사용한다(`all_messages[-500:]`).
앞부분이 아니라 **뒷부분(tail)**을 남기는 이유:

- 방장을 돕는 요약·액션 아이템의 목적상 **최근 대화의 미해결 이슈**가 가장 가치 있다.
- 오래된 상단 메시지는 이미 처리됐을 가능성이 높다.

컷이 발생하면 템플릿에 `truncated=True`를 전달해 UI가 "최근 N개만 분석됨"을 알린다(조용히 버리지 않는다).

## Consequences

- 500은 토큰 한도·비용·요약 품질 사이의 경험적 균형점이다. 모델/`max_tokens`을 바꾸면 이 숫자도 재검토한다.
- head가 아니라 tail을 남기는 선택이 핵심이다 — 되돌릴 때 이 의도를 깨지 않도록 주의.
- 상세는 [`../../api/CLAUDE.md`](../../api/CLAUDE.md)의 "메시지 수 제한" 참고.
